# 队友 A：GridDehazeNet 定点网络与 Golden

## 你负责什么

将 [总说明](README.md) 固定的官方 outdoor 模型变成可实现、可逐元素验证的整数计算规范。先保留原网络效果，不在本轮顺手换模型、剪枝或蒸馏。

## 立即开始的三件事

1. 用固定提交源码和指定 SHA256 权重复现 FP32 推理，先跑一张用户认可的雾图。
2. 给 B 一份按执行顺序排列的算子清单，包括形状、连接、权重、缓存依赖。
3. 和 B 对齐输入/输出布局、量化尺度、融合规则及 scratch 需求，再开始定点实现。

## 必须保留的模型语义

- 输入 **RGB NCHW**，像素 `v` 对应浮点值 `v / 255 * 2 - 1`，范围 `[-1,1]`。旧 TinyRestore 的 `[0,1]` 预处理不能直接沿用。
- 输出是网络 ReLU 后的非负值，可能超过 1；显示时再 clamp 到 `[0,1]` 并转换 RGB8。Golden 需明确是显示前还是显示后，本轮建议整数网络输出与显示转换分别定义。
- `Conv2d`、`ConvTranspose2d`、ReLU、dense concatenation、残差/多分支加法、按通道 learned coefficient 乘法都要覆盖。
- `coefficient` 是训练后的参数，不能按构造时的全 1 替代。上游的融合不是可以随意替换的动态注意力。
- 转置卷积使用目标特征的 `output_size`，奇数尺寸时尤其不能按固定乘二输出后随意裁剪。
- 零填充、通道拼接顺序、各尺度分辨率必须与上游一致。

## 定点工作内容

建议从 INT8 权重、INT16 特征开始评估，**这是候选格式，不是已验收格式**。每层累加范围按真实通道数和核大小分析，不能直接假设 INT32 永不溢出。

请交付：

- 每层/每通道 scale 或 frac，权重和 bias 格式，signedness、乘法及累加位宽。
- bias 对齐、融合加法对齐、舍入、饱和、截断的精确顺序。
- coefficient 的独立定点格式，或明确证明等价的融合方法；不要隐式使用 FP32。
- 各算子与完整网络的整数参考程序，以及中间节点转储入口。
- 权重二进制及 manifest：源提交、权重 SHA256、量化配置、文件长度、哈希、布局。
- 对称量化与输入 Q14 可作为起点；例如 signed Q14 的 `[-1,1]` 需要保留负数，不能沿用旧接口只接收 `[0,16384]` 的假设。

## 校准与效果验收

1. 明确校准集、验证集和独立测试集。不要用全部 Fog 图片校准后，再把这些图片上的误差称为泛化性能。
2. 在同一张输入上对比 FP32 与整数输出：MAE、最大误差、各节点饱和次数及可视化。
3. 校准误差不是恢复质量：真实 Fog/Rain 没有清晰真值，不能对原图计算“去雾 PSNR”并称越高越好。
4. 可用有清晰配对的去雾测试图补充质量指标；写明数据划分。用户认可的真实图和浓雾/逆光/夜景边界图必须保留视觉对比。
5. 若出现明显偏色、边缘光晕或细节损失，先调整量化，报告问题，不能靠额外调色掩盖数值错误。

## 提供给 B 的最小测试向量

- 至少一组完整图片输入/输出，包括用户认可样例；传输图片前由用户提供其本地文件，不假定队友电脑有 Downloads 路径。
- 小尺寸 33×47 等非整除尺寸，用于多尺度和边界验证。
- 1×3×675×1280、1×3×720×1280 的大图用例；不支持的尺寸要明确报错，不静默拉伸或裁剪。
- 黑图、白图、通道常量、脉冲或边界图，检查输入负数、padding 和转置卷积位置。
- 每组附布局、维度、文件字节数和 SHA256；区分 FP32 参考与整数 Golden。

## 完成条件

**整数参考、权重、逐节点格式表和测试向量可独立重放，并且定点视觉效果被确认可接受。** 未做到之前，不宣称新模型具备 FPGA 可部署性或板端通过。

自动雨雾分类与去雨模型目前不作为该模型定点交付的前置依赖；需要预留后续扩展接口，但不能把当前 78% 分类原型当正式检测模块。
