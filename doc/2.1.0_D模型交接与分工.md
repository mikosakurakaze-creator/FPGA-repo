## 2. 需要原样实现的数值语义

| 项目 | 冻结内容 |
|---|---|
| 输入 | RGB，batch=1，NCHW；先浮点RGB8/255，再*2-1 |
| stem | Conv2d 3→8，3×3，stride1，padding1，bias=True；ReLU |
| block ×3 | 8→8 Conv3×3 → ReLU → 8→8 Conv3×3 → 与block输入相加 → ReLU |
| head | 8→3 Conv3×3，线性输出，可为负数 |
| 原图旁路 | `(x+1)*0.5`，与head结果相加，再ReLU |
| 网络输出 | 只限制下界0，允许大于1；显示阶段才裁到[0,1] |
| 显示 | clamp后×255，np.rint（最近偶数）再转uint8；不要与整数重定标规则混为一谈 |
| 卷积 | groups1、dilation1、零填充；PyTorch权重OIHW，bias按输出通道 |
| 参数 | 3947，16个参数张量；没有BN、attention、concat或deconv |
| FP32参考图 | 22个语义节点；不是已冻结的整数图或硬件ABI |

软件读图先处理EXIF方向，转RGB，等比缩小至1280×720以内，不裁剪、不拉伸、不放大小图。
FPGA实际处理尺寸及计时必须报告，不能把320×180结果放大后称为720p原尺寸推理。

## 3. 队友 A：算法、定点参数、整数 Golden

1. 先用交付的独立 `predict.py` 重现 D 的 FP32 软件效果；核对权重SHA和3947参数。
2. 用 `reference_fp32/manifest.json` 和原始FP32权重核对8层卷积及输入旁路，
   两组随机小图为8×8及33×47；此参考仅用于结构/浮点检查。
3. 校准INT16权重和激活格式，输出每层缩放、bias格式、乘加位宽、重定标与饱和规则。
   重点处理两个残差分支的尺度对齐以及head的有符号修正量。
4. 明确每个量化边界；融合算子时必须保持约定的舍入与饱和次序。
   INT16输出为正式目标起点，若改INT8须另交画质和误差证据。
5. 对认证参数给出乘加绝对界证明；原Grid的48位证明不能自动沿用。
6. 交付可执行整数参考、图、参数blob、偏移及dtype清单、身份manifest、溢出证明。
7. 提供黑、白、灰、通道、随机、奇数尺寸、小图及720p的输入和整数Golden，
   并提供真实雾图/雨图上FP32与定点的可视化对比。无需重复旧Grid长测。

验收：同一输入下，整数参考可复现；参数及Golden均有SHA256；
无明显新增偏色、过暗或细节损失，再交B固定版本。
去雨效果需独立评估，不能把去雾蒸馏目标当成去雨真值。

## 4. 队友 B（wzh）：精简引擎、缓存、镜像

1. 与A对齐定点图、参数及身份，再改HLS/RTL；D只需普通卷积、ReLU、残差加法、输入仿射旁路。
2. 删除旧Grid的网格调度、concat和deconv路径及闲置旧IP，释放DSP、BRAM/URAM和布线资源。
   不要破坏PS上传、显示、共享时钟/复位和所需AXI接口。
3. 针对8通道结构评估输入/输出通道并行，检查实际achieved II、乘法器数量和存储bank。
   之前64路Grid候选只能作参考，不是已验证的D加速器。
4. 优先评估行缓存/流式卷积、卷积后ReLU融合、残差分支延迟对齐和片上复用，
   减少完整特征图反复往返DDR；根据资源报告决定方案，不能只提高时钟。
5. 提供总周期、输入/参数加载、计算和输出写回的计数，
   明确各阶段是否重叠；可重叠计数不能直接相加解释总耗时。
6. 与软件侧确认寄存器表、模型ID、ABI版本、输入输出格式、最大尺寸、参数/缓存长度、
   地址位宽/对齐、DMA完成与idle条件、错误状态和超时后的DMA所有权。
7. 输出HLS资源及调度报告、RTL小图Golden、Vivado routed资源/时序、bit、bit.bin、XSA、HWH及SHA。
8. 先小图板测，正确后只做必要的720p验收；分别报告核心延迟和完整请求延迟。

不要在未完成DMA时释放缓冲区或假设复位已阻止所有AXI写入。
D的新寄存器或身份未确认前，不使用旧Grid驱动启动新镜像。
