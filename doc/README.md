## 当前决定

- 本阶段只完成单张图片，不设置视频帧率门槛。
- 去雾采用 **GridDehazeNet 官方 outdoor 权重**作为基线；不擅自修改结构、换权重或重新训练。
- 去雨尚未选定：PRN/PReNet 已做电脑对比，尚没有充分的效果证据支持正式采用。
- 不固定“去雾→去雨”串联；同一张暴雨图上的两种顺序差异有限，串联还有平滑细节的问题。
- 最终用户只上传图片，由系统判断天气、增强并在板子 HDMI 显示，可下载结果。
- 自动判断第一版只有 fog/rain 两类，在 400 张训练图、100 张验证图上选出的最佳准确率为 78%；没有独立测试，近重复和摄像头重叠未排除，也没有晴天、混合天气标签。**不能当作已经完成的产品功能。**

## 已验证与未验证

| 项目 | 证据与状态 |
|---|---|
| 旧 TinyRestore | 已有 signedfix 板端 Golden 通过，不代表新模型已上板 |
| GridDehazeNet | 官方权重严格加载成功；参数 958,051；电脑实际推理成功 |
| 效果 | 用户认可 `foggy-001` 上的去雾结果；其他浓雾图仍可能改善有限，不宣称整体质量达标 |
| 图导出 | 本地 torch.fx 导出图在一张 1×3×675×1280 输入上与原始 FP32 网络逐元素一致 |
| 计算量 | 720p 卷积约 263.12 GMAC/帧，来自 64×64 算子计数的面积外推；转置卷积包含部分填充乘法，未计融合、访存、调度，不是板端性能 |
| 新模型定点化/HLS/RTL/综合/布局布线/上板 | **均未完成**；当前板上仍是 TinyRestore |
| 工具 | 新版 Vivado 在队友电脑；用户本机发现的是 Vivado 2017.4，不在本机生成新镜像 |

## 阶段顺序与验收

1. A/B 固定网络版本、算子语义、接口及内存约定。
2. A 提交整数参考和定点效果对比，先确认没有明显偏色/大幅画质损失。
3. B 完成算子验证、网络验证、综合实现，报告真实资源及时序。
4. 软件侧适配驱动；板端单张图逐元素对齐 **整数** Golden，确认输入与缓冲区边界未破坏。
5. 接入图片上传→处理→HDMI→下载。测量核心耗时及完整请求耗时，分别报告。
6. 去雨与自动识别另行通过效果验收后合入，不为了凑齐界面功能假装已经可用。
