INT16 激活逐节点 F 从 3 到 14，输入 F14、最终输出 F13。依据 50 条校准记录（47 个独立原始 SHA）的中心 64×64 裁剪及 10 个明确的合成校准探针，使用 2 倍范围余量选择二进制尺度。没有用验证图片重新校准。每通道真实权重的最大保守累加绝对界为 286,417,368,313，至少需要 signed 40 位；参考实现统一用 INT64。B 可用清单证明缩位，不能假设 INT32 无溢出。

## 浮点与定点误差

误差在显示 clamp 前按各自尺度还原后与同输入官方 FP32 比较，单位为网络输出实数；这些数值不构成未经负责人确认的验收阈值，也不是去雾恢复质量 PSNR。

| 测试 | MAE | 最大绝对误差 | 节点饱和 | 整数 CPU 耗时 |
|---|---:|---:|---:|---:|
| 33×47 固定随机输入，INT16 | 0.000220409 | 0.000968099 | 0 | 见 case 原始报告 |
| 15 张真实验证图中心 64×64，INT16 | 0.001981792（平均裁剪 MAE） | 0.009146243 | 0 | 见原始报告 |
| 同 15 张裁剪，INT8 | 0.003563150 | 0.034813523 | 0 | 见原始报告 |
| foggy-001 原图 675×1280，INT16 | 0.001777002 | 0.011797547 | 0 | 264.539 秒 |
| 固定随机 720×1280，INT16 | 0.000219579 | 0.001444578 | 0 | 298.141 秒 |

大图均实际执行完整整数网络，再单独运行官方 FP32 最终对比；没有缩放、裁剪或用浮点近似执行整数算子。大图保存原始输入、最终网络 raw、显示 raw、FP32 raw，以及全部 320 节点的 SHA/范围/饱和；**未保存全部大图中间原始文件**。所有小 Golden 则保存全部中间原始文件。大图没有重复执行第二种完整整数后端，双后端全图精确证据来自 33×47，算子另有独立标量 Oracle。

## 数据与容量

Fog 300、Rain 200 张原图来自主人本轮 ZIP。50 校准/15 验证/435 保留文件划分固定；16 组相同字节图保持同一集合，未发现原始 SHA 跨集泄漏。尚未审核近重复或相机场景重叠；保留集没有运行，不能宣称独立测试质量达标。Rain 在这里仅为去雾模型的边界输入，没有执行去雨模型。

`archive.zip` 实际是 3,391,982,600 字节的摄像头/热成像数据，26,624 个文件，仅做 SHA 和清单记录，没有解压或假设是模型包。另下载的官方 SOTS 单组样例仅作来源检查，最终报告的 15 张验证不是 SOTS 基准。

720p materialized INT16 图理想及时释放峰值为 353,894,400 字节；675×1280 为 331,816,960 字节。720p 不释放所有节点合计 8,019,763,200 字节。它们是明确假设的逻辑容量，**不是 B 设计的批准 DDR scratch，也不是 Python RAM 实测**；未包含地址碎片、双缓冲和后端提升。逐节点形状、生存期及目标反卷积 output_padding 见 `run_003/plan_*.json`。

1. 依赖下载在 pip 的二进制下载步骤停滞；保留 install 日志，改用固定官方 torch wheel 的 curl 下载及镜像依赖安装后完成。wheel SHA256 为 `2be20b2c05a0cce10430cc25f32b689259640d273232b2de357c35729132256d`。
2. 首次严格加载因官方 `module.` 前缀失败；显式验证统一前缀并去除命名空间后严格加载。旧失败及新成功命令均保留。
3. 首次输入转换产生非连续 NCHW，整数入口正确拒绝；修复连续布局并增加覆盖所有 256 像素级与通道空间顺序的测试。
4. `run_001` 统一 Q10/Q12 发生大量饱和，未作为交付方案。`run_002` 逐节点真实裁剪校准对随机边界仍有饱和；增加明确的合成**校准**探针后生成最终 `run_003`，不能把探针上的结果称为独立泛化性能。

历史输出和失败日志没有删除。旧包身份会因数值源码/配置变更被当前加载器拒绝，不能复用其 Golden。最终复现应使用交付的冻结配置；以新代码重导出旧方案会产生新身份。
