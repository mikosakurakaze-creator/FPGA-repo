# 天气恢复数据流

本文区分原 A 组 v1 tile 路径、历史串行整帧原型和当前整帧流水版。当前构建结果见 [流水版报告](stream_revision_20261020.md)。

## 工作模式

| 模式 | 处理路径 | 约定 |
|---|---|---|
| 旁路 | 输入帧 → 输出/显示 | 清晰场景保留旁路能力。 |
| 低照度 | 原低分辨率 CNN → Bilinear → Curve | 沿用 V1.2 路径、ABI 和算术。 |
| 去雨（v1 参考） | 整帧 → 去雨 tile 调度 → 固定去雨 IP → 整帧输出 | 使用去雨 IP 及其内置权重/缩放参数。 |
| 去雾（v1 参考） | 整帧 → 去雾 tile 调度 → 固定去雾 IP → 整帧输出 | 使用去雾 IP 及其内置权重/缩放参数。 |
| 去雨/去雾（当前 v2） | 整帧 DDR → `weather_frame_top` → 整帧 DDR | 同一核通过 `task=0/1` 选择固定模型，内部采用行缓存流水。 |

原两个天气 v1 IP 的 ABI 相同，但固定参数不同，模式选择必须对应正确 IP。自动场景判定由后续软件实现，首次上板采用手动模式。已公布的清晰图测试显示去雾可能改变正常图像，因此仍需旁路。

## 原 ABI v1 分块路径

A 组 top 每次接收一个连续 `[1,3,H,W]` tile，`1 <= H,W <= 140`，无整帧 stride 或 AXI Stream 输入。处理全分辨率帧时，主机或 tile DMA 需要：

1. 选择 128x128 输出 core。720x1272 对应 6 行、10 列，共 60 个 tile。
2. 从平面 RGB Q14 整帧中收集 core 加六像素 halo，生成紧凑 NCHW tile。真正图像边缘处裁剪 halo，不在图像外补造有效输入。
3. 同步/清理打包输入供设备使用，分配互不重叠的 input、output、scratch，再配置所选固定 IP。
4. 等待完成和返回状态 0，按平台要求将输出所有权同步给 CPU 或后续设备。
5. 只将 tile 输出中的 core 像素复制到整帧输出的对应区域。
6. IP 完成全部读写之后才复用 tile 缓冲区。

A 组 `run_image.py` 展示主机调度，集成报告检查了拼缝和边缘一致性；它不是板端 DMA 实现。A 组集成 Golden 使用 145x149、core 64/128，接入系统数据收集/回写后仍需保留这些测试。

B 侧 `deployment/weather_tiled.c` 已用可移植所有权/控制回调实现 CPU 路径。主机模拟测试调用原 A 组 C++ 核，两任务、两种 core 尺寸在 145x149 上与整帧原型逐位一致；真实 DMA/MMIO 绑定和板测仍待完成。

## 整帧 ABI v2 路径

`weather_frame_top` 接收整帧 NCHW Q14 输入/输出 DDR 地址和 task 选择。无外部特征工作区，也无需 CPU 逐 tile 复制。它使用 ABI v2，与已打包的 A 组 v1 IP 的 CSR 布局不同，接入前需阅读 [v2 合同](weather_frame_v2_contract.md)。原 v1 IP 仓库保留。

历史 `experiments/onchip_frame` 在 PL 中收集裁剪后的 halo 行，复用片上 RGB/main/depth bank，仅写回 core。当前 `experiments/stream_frame` 已改为整帧读行 → RGB 重排 → stem → 五个残差块 → tail → NCHW 重排 → 写行；各空间阶段使用独立两行缓存和窗口，输入输出各访问一次。

两任务 Golden 节点、720x1272/720x1280 主机比较、HLS、连续切换 RTL、独立反压 RTL 及两任务完整 720p RTL 均通过。当前组合系统布局布线和 bit/XSA 已完成；完整帧独立 DDR 模型下各为 3,009,677 拍。该周期不是实际视频 FPS，具体证据和限制以当前报告为准。

## 首次上板验收

当前 v2 优先运行 `deployment/standalone/` 的三次 8x8 Golden/越界保护最小测试，再执行尺寸切换、整帧和连续帧。若验证原 v1 回退路径，则先运行主机准备的单 tile，再经 tile 调度处理完整帧。

原始 Q14 输出应与独立整数参考逐字节比较，保存输入输出哈希。初期串行调用；原 v1 的每次活动调用使用独立 scratch。所有权和缓存切换通过后再增加乒乓缓冲。

实时路径应使用适合平面行的 DMA/数据收集回写方案，避免长期由 PS 逐像素复制。CPU 复制可用于临时正确性联调，但必须单独计时，不能视为 FPGA 吞吐结果。

## 集成边界

天气核直接写增强 RGB，不产生 `A_low`，无需旧 Bilinear/Curve，也不能把天气 RGB 输出当作参数图送入这两个阶段。摄像头采集、显示、自动天气模式选择、Linux DMA/缓存策略、低照度共存和整机持续吞吐仍需单独实现和验证。
