# 团队 Git 协作规范

## 分支原则

- `main` 始终保持稳定，只接收经过检查的合并。
- 每位成员从最新 `main` 创建自己的开发分支，分支名应体现任务内容。
- 不直接在 `main` 上开发、提交或推送。
- 不直接修改、覆盖或强制推送其他成员的开发分支。

## 推荐流程

1. 开始任务前获取远程更新，并确认本地工作区干净。
2. 从最新 `main` 创建个人功能分支。
3. 将改动拆分为职责清晰、可审查的提交，不提交数据集、权重、生成文件、密钥或本机环境信息。
4. 推送个人分支并创建 Pull Request，描述改动、接口影响和验证情况。
5. 经代码/文档检查和必要验证后再合并到 `main`。
6. 若接口发生变化，先更新 `docs/interfaces.md` 并通知相关上下游成员。

合并冲突应由分支负责人结合最新 `main` 处理；禁止通过 force push 覆盖公共协作历史。
