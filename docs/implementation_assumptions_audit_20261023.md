## 本轮诊断代码发现并修正的实际问题

1. `tools/run_board_repro.py` 原先仅按仿真完成退出 0，数值不匹配也可能退出成功。现在分开记录 `completed` 与 `pass`，只有全部指定帧完整且 Golden 不匹配数为 0 才退出 0；未知值不能通过。双任务回归固定检查四帧 task=0、0、1、0。
2. 原端口宽度解析按名字猜测默认宽度。现在解析实际 HLS 参数及端口范围，遇到不支持的表达式直接失败，不静默套用默认值。
3. 原网表 trace 曾准备对优化后的阶段总线补 16 位 0，这不具备逐位恢复依据；没有拿该路径形成验证结论。现在禁止网表逐阶段 trace 的猜测恢复，导出 RTL 的原始完整 176-bit trace 可用。
4. 布线后天气核实际多出 `pwropt`、两路复制后的复位输入，不能照综合前接口直接仿真。进一步发现，孤立导出子模块会保留端口名但移除常量位或改变方向；仅拼接子模块不等于恢复原系统。现已禁用这种入口，保留原始父层中天气核、控制/数据 SmartConnect 和复位的真实连线，不猜复位极性或绑常量。
5. 原先提取全文中可见的 `module/endmodule` 会漏掉加密的 SmartConnect 模块体，导致 elaboration 不完整。现在完整原网表原样附在诊断外壳后，未完成 elaboration 的运行不计为通过。
6. 实际 PS HPM 控制总线是 128 位，初版诊断外壳沿用 32 位 AXI-Lite 假设，没有处理 CSR 窄访问的字节通道；HP 的 ID 位宽和响应回传也没有按 PS 声明完整适配。现在从实际 PS 模块声明提取位宽和方向，按地址移动 WDATA/WSTRB、抽取 RDATA、返回 ARID/AWID。未寻址的低照度控制目标响应显式模拟为空闲，避免悬空 X 污染仲裁；这是仿真替身，不能说已模拟低照度整核并发运行。
7. Verilog `while(!READY)` 对 X 的处理可能提前退出握手等待。诊断平台改为 `READY !== 1'b1` 才继续等待，并把固定 8×8 诊断的全局超时从原 720p 测试的 600ms 缩短到 500us，防止悬空接口长时间运行而没有有效数值结果。
8. 新结果增加测试平台、脚本、模板和网表哈希，明确独立内存模型及实际 SmartConnect 的覆盖边界。早期子模块拼接失败、完整路径第 3 次尝试中止，均没有产生两帧有效输出，不能称为“布线后功能通过”或“复现板端失败”。
9. 补全输出解析：固定用例必须恰好 192 个四位十六进制标量；数量不足、非法编码和 X/Z 均记录失败，不再因 `struct.unpack` 异常中断证据报告。DSP 属性提取限制在当前 primitive 的参数块内，避免宽松正则跨前一个 DSP 匹配到错误属性。

## 已直接观测的实现问题

`board_diag_20261023_physical_path04` 连续两次调用均得到与真板完全相同的 384 字节和 SHA-256。逐级观察原网表的实际 FIFO 输入端口，前五级全部一致，RGB 六级全部一致；第六级只有特征通道 2 的 57 个像素被变成 32767。该观察不补造已经删除的符号位。

残差相加/比较信号符合实际操作数；它的点卷积操作数已经错误。量化幅值寄存器在首个像素前取得 65976，正常应为 440，相差 65536。对照原综合与实现网表发现，一个 DSP 接收端原来的 `sign_extend(previous_P[21:0])` C 加数改成了前级完整 48-bit PCOUT。实测前级 PCOUT[21]=1、PCOUT[22]=0 时，两种语义不同。只恢复这一处 C/PCIN/OPMODE，两次调用均 192/192 等于 Golden；这确认了本组数据在实现模型中的原因，不等同于已经修复实际 bit。

新增构建保护也必须以结果为准：第一次只对接收 DSP 加 `DONT_TOUCH` 的试验没有阻止连接变化，已经拒绝该候选。没有因为属性设置成功就宣称修正成功。关闭对应 DSP cascade fixing 后，优化网表和重新布线的网表均完成四帧双任务/暖态数值回归，全部通过。新布线100 MHz setup为+0.638 ns，hold为+0.010 ns，166,311/166,311条可布线net全部完成。

本轮自审又发现初版保护检查只比较 C[21] 与 C[22] 是否相同；错误版本把整个 C 绑成1时也可能满足这种弱检查。它只是一条不充分的结构断言，不能作为发布资格。现改为逐位核对 C[0:47] 是否来自前级 P[min(bit,21)]，并核对实际 OPMODE 的 Z 选择及反相属性。旧错误 opt 检查点被拒绝，新 routed 检查点通过。Vivado 未设置的反相属性为空，已对照本机 DSP48E2.v 的0默认值处理；早期属性编码检查失败保留为诊断工具失败，不计数值验证结果。

发布的三个入口均加入同一份布线数值门禁：`package_release.py`、`board_artifacts.py collect`、`collect_signedfix_release.py`。门禁除读取 PASS，还重新比较四份384字节实际输出、Golden、输入身份、任务顺序、执行脚本快照和仿真日志；本轮已执行错网表哈希、改Golden、截短输出、改输入、缺执行源和改task的六项私有副本负对照，全部拒绝。

另修正 `deployment/standalone/main.c` 的输入不变性检查：正常 device-read 结束后后端无需失效输入缓存，直接 CPU 比较可能读到旧缓存。本测试现在先显式失效活动输入区域，再检查是否遭到非法PL写入。该源代码修改没有重新编译为 A53 ELF，也没有上板，不能写成已验证的板端修复；本次实际硬件原因来自 DSP 数值通路。

## 冻结整数参数是否凭空选择

本轮没有重新选择位宽或标定参数。新增 `tools/audit_integer_contract.py` 直接解析两份冻结头文件，核对24层的通道、分组、卷积尺寸、INT8权重范围、INT16节点、相邻小数位、移位范围和保守 INT32 界限：

| 模型 | 全有符号INT16输入下最大MAC绝对界限 | 量化右移范围 | 最大残差加法绝对界限 |
|---|---:|---:|---:|
| 去雨 | 48,004,779 | 5～11 | 65,536 |
| 去雾 | 48,034,234 | 4～11 | 98,304 |

以上均在 INT32 内，证据为 `evidence/source_integer_contract_20261023.json`。这是源码整数规则的界限检查，不能证明 HLS/Vivado 缩窄并改写后的网表等价；本次正是必须另外验证网表的例子。

以上第 4～8 项是本轮诊断代码的真实缺陷，已经在调查中更正；它们没有被用于生成当前已发布 bit，不能拿来冒充板端根因。

## 新取得的数值特征与边界

新增 `tools/analyze_board_signature.py` 和 `evidence/board_mismatch_20261023_signature.json`。先用六级空间阶段最后一级的原始完整导出 RTL trace 与原始尾层整数权重重新计算，验证 192/192 等于 Golden、RGB 等于输入，再做假设注入：

- 用最终输出差异得到 57 个错误像素位置，逐一测试把 8 个候选特征通道之一设成 INT16 正饱和值 32767。
- 只有零基第 2 号特征通道的注入可以复现全部 192 个板端标量，SHA-256 也与真板一致；两次导出 RTL trace 都得到此结果。
- 57 个位置的正常该通道数值范围是 0～1679；其余 7 个像素位于 `y=1..7,x=2`。

这项分析把“末级特征通道 2 的饱和/选择通路”列为优先观测对象。它不是实际板内通道读回，空间掩码来自已经知道的最终错误位置，因此不能由此宣称唯一定位了 URAM、某个寄存器或 DSP 的根因，也不能把这份假设注入当修复。

## 已取得而无需再猜的信息

- 输入、Golden、板端输出、bit、XSA、BIN 的 SHA-256 已核对；数据都是 RGB NCHW、小端 INT16 Q14、8×8、task=0。
- 实际生成驱动/RTL 的 CSR 为 input `0x18/0x1c`、output `0x24/0x28`、height `0x30`、width `0x38`、task `0x40`，天气控制基址 `0xA0030000`。
- 编译使用的 254 份 RTL/ROM 与导出来源一致，天气综合检查点身份一致。
- 输入/输出经 HP0/HP3；HLS master 为 32-bit，实际 SmartConnect 面向 PS 端为 128-bit。地址在允许的低 2 GiB 窗口且不重叠。
- 用户实测四个 AFI 寄存器均为 `0x000003B0`，只支持“低两位字段匹配”的结论。
- 首次及暖态同样错误，不能用“多跑一次就会正常”处理，也不能由此直接判断缓存已排除。

## 仍缺少的关键证据

- 实际 FPGA 内配置身份的独立回读，以及本次调用在 HP0 收到的原始数据、在 HP3 发出的原始数据与响应；磁盘中 bit 的哈希不等于读取了器件配置内容。
- 修正版的真板复测仍需进行。若新文件仍有错误，再观测实际 HP 数据或首个偏离点；当前没有 ILA 或逐级 readback。原版本则已经在实际布线功能模型中确认因果链，无需继续把完整离线结果描述为“全部正确”。
- 板端完整 PS 初始化/安全和地址翻译状态、物理运行条件，以及持续帧和任务切换结果。不能拿四个 AFI 字段代替这些信息。

## 验证原则

按同一输入依次区分源码、导出 RTL、综合后功能网表、布线后功能网表、实际 SmartConnect 路径、真实板卡。功能网表仿真不含 SDF，不声称已覆盖板上物理时序。出现“离线全对、板端仍错”时继续缩小边界；不把重新生成一个 bit 当成根因修复。

本次实际执行了从已链接综合 DCP 开始的修正、opt、place、phys_opt、route、严格连接核查及最终网表数值回归。新挂接的全新 project `create→synth→impl→package` 路径没有从头再跑一次；不能把其源码检查等同于已实际完成整条新工程重建。工具参数对当前 Vivado 进程全系统生效，最终诊断中其他低照度 master 空闲，低照度并发和整网数值回归另需验收。
