# Zero-DCE++ 当前定点格式与模块接口说明

版本依据：`fpga program` 仓库 `feat/zero-dce-quantization` 分支，提交 `0d2dbb2`。整理日期：2026-09-25。

本文描述**当前代码实际采用的数值规则**。CNN 的 14 层卷积、ReLU、拼接、Tanh 查表及低分辨率参数图输出已有 HLS C++ top；下采样、参数图双线性插值和八轮增强的定点规则目前由软件整数原型实现，尚无对应的 HLS 核。模块间若改用 AXI Stream，仍需保持本文的数值和数据排列约定。

## 1. 记法和总体链路

`QF` 表示二进制小数位数为 `F`，实值为 `有符号原码 / 2^F`。存储位宽需另行指定。例如“INT16 Q14”是有符号 16 位整数，原码 16384 表示 1.0。当前整数规则均采用对称定点，零点为 0；没有仿射量化的非零 zero point。

```text
RGB UINT8 原图 720×1280
  → 裁剪至 720×1272；归一化为 Q14；12 倍整数下采样
CNN 输入：INT16 Q14，[1,3,60,106]，RGB 平面 NCHW
  → 7 个深度卷积 + 逐点卷积模块，合计 14 层
  → Tanh Q15 查表、Q15→Q14
CNN 输出 A_low：INT16 Q14，[1,3,60,106]，RGB 平面 NCHW
  → 双线性插值，得到完整参数图 INT16 Q14，[1,3,720,1272]
  → 与完整原图一起执行八轮 Q15 曲线增强
增强结果：INT32 Q15 → RGB UINT8 图像
```

当前 CNN top **不负责裁剪、下采样、插值或增强**。它读取已经下采样的 `[1,3,60,106]` 图像，并将 `A_low` 写入 DDR。

## 2. CNN 逐层 Q 格式

每层输入和输出激活均为有符号 INT16。权重为有符号 INT8，按**每个输出通道分别选择**小数位 `F_w`。下表的 `F_w` 为该层通道值的最小～最大值；实际逐通道列表以 `configs/zero_dce_pp_integer_rules.json` 为准。所有层空间尺寸均为 `60×106`，步长均为 1。

| 层 | 输入通道→输出通道 | 输入 Q→输出 Q | 权重 `F_w` | 核 / groups |
|---|---:|---|---:|---|
| `e_conv1.depth_conv` | 3→3 | Q14→Q14 | 8 | 3×3 / 3 |
| `e_conv1.point_conv` | 3→32 | Q14→Q14 | 7～16 | 1×1 / 1 |
| `e_conv2.depth_conv` | 32→32 | Q14→Q13 | 8～16 | 3×3 / 32 |
| `e_conv2.point_conv` | 32→32 | Q13→Q14 | 8～16 | 1×1 / 1 |
| `e_conv3.depth_conv` | 32→32 | Q14→Q14 | 7～16 | 3×3 / 32 |
| `e_conv3.point_conv` | 32→32 | Q14→Q14 | 7～16 | 1×1 / 1 |
| `e_conv4.depth_conv` | 32→32 | Q14→Q12 | 7～16 | 3×3 / 32 |
| `e_conv4.point_conv` | 32→32 | Q12→Q12 | 7～16 | 1×1 / 1 |
| `e_conv5.depth_conv` | 64→64 | Q12→Q13 | 7～16 | 3×3 / 64 |
| `e_conv5.point_conv` | 64→32 | Q13→Q13 | 7～16 | 1×1 / 1 |
| `e_conv6.depth_conv` | 64→64 | Q13→Q13 | 7～16 | 3×3 / 64 |
| `e_conv6.point_conv` | 64→32 | Q13→Q14 | 8～16 | 1×1 / 1 |
| `e_conv7.depth_conv` | 64→64 | Q14→Q14 | 8～16 | 3×3 / 64 |
| `e_conv7.point_conv` | 64→3 | Q14→Q16 | 9 | 1×1 / 1 |

深度卷积的 3×3 核使用四周零填充 1 个像素；逐点卷积无填充。每组 `point_conv` 后接 ReLU，**第 7 组除外**。各层之间在必要时先将上一层输出按下一层 `F_in` 重新定标，不能仅因两者都用 INT16 就直接传原码。

## 3. 乘法、累加与重定标

对任意卷积层的输出通道 `c`：

```text
F_acc[c] = F_in + F_w[c]
acc[c]   = bias_int32[c] + Σ(input_int16 × weight_int8[c])
out[c]   = sat16(round_even(acc[c] × 2^(F_out − F_acc[c])))
```

`bias_int32[c]` 与乘积采用相同的 `F_acc[c]`，由浮点偏置按 `round_even(b × 2^F_acc[c])` 导出。乘积的数学有效位宽为有符号 **24 位**（16×8）；当前 HLS 源码先将两个操作数都转成 `ap_int<32>`，因此 C++ 乘法表达式为 **64 位**，每次乘加后写回 **`ap_int<32>` 累加器**。当前导出参数计算的最大最坏情况累加绝对值上界为 **383,670,400**，低于 INT32 上限 2,147,483,647。软件原型使用 INT64 容器执行卷积，再检查 INT32 范围。

重定标规则：

- 减少小数位时，按有符号“最近整数、正中取偶”（ties to even）舍入；正负值对称。例如 `−1/2 → 0`、`−3/2 → −2`。
- 增加小数位时乘以 `2^n`；不直接截掉低位。
- 卷积输出和层间换算在舍入后饱和到有符号 INT16 范围 `[-32768, 32767]`。ReLU 随后将负值改为 0。
- 导出的逐层正确输出位于“重定标和 INT16 饱和之后、ReLU 之前”。
- 权重离线量化采用最近偶数舍入，并钳到 `[-127,127]`。

这里的“64 位乘法表达式”描述当前 HLS C++ 类型；最终综合器可能依据操作数的有效位宽优化电路，并不表示每个乘法器都必须是物理 64×64 位。

## 4. Tanh 和 CNN→插值接口

末层逐点卷积输出为 **INT16 Q16**。先按最近偶数规则转成 Q8 索引，将索引限制在 `[-2048,2048]`，再用 `索引+2048` 访问 4097 项 **INT16 Q15** Tanh LUT。LUT 离线生成，覆盖输入约 `[-8,8]`。输出接口转换为：

```text
A_low_q14 = sat16(round_even(tanh_q15_raw / 2))
```

`A_low` 为 **INT16 Q14**，形状 `[1,3,60,106]`，实值 `raw/16384`。这是当前 CNN HLS 与后级 Bilinear 的固定边界。

| 项目 | 当前约定 |
|---|---|
| 通道顺序 | R、G、B |
| 排列 | NCHW，C 连续平面；一个通道的全部 60 行存完后才是下一通道 |
| 元素索引 | `((c × 60 + y) × 106 + x)` |
| 字节偏移 | `2 × ((c × 60 + y) × 106 + x)` |
| 数据编码 | 有符号 INT16 二进制补码，小端，无头、无行填充 |
| 单通道 / 整帧 | 12,720 字节 / 38,160 字节 |
| 当前传输 | CNN `m_axi` 写 DDR；`ap_done` 后同帧 Bilinear 读取 |

当前 top 使用 AXI4-Lite `ap_ctrl_hs` 控制；**没有 AXI Stream 输出**。输入、模型数组、输出、工作区需使用互不重叠的 DDR 区域，并在 `ap_done` 前保持有效。PS 启动前刷新输入、权重、偏置、小数位和 LUT 缓存；读取 `A_low` 前失效其缓存。物理 DDR 基地址及生成后的 AXI-Lite 寄存器偏移尚由系统集成阶段确定。

## 5. CNN 权重与内部工作区排列

| 数组 | 元素数量 | 类型和排列 |
|---|---:|---|
| `input_q14` | 19,080 | INT16 Q14；`[1,3,60,106]` RGB NCHW |
| `weights_int8` | 10,075 | 按上述 14 层顺序拼接；每层 OIHW，深度卷积遵循分组布局 |
| `bias_int32` | 486 | 按层、再按输出通道拼接 |
| `weight_frac` | 486 | 有符号 INT8；按层、再按输出通道拼接，每通道一个 `F_w` |
| `tanh_lut_q15` | 4,097 | INT16 Q15；对应 Q8 索引 `−2048…2048` |
| `a_low_q14` | 19,080 | INT16 Q14；`[1,3,60,106]` RGB NCHW |
| `workspace_int16` | 1,221,120 | INT16 DDR 工作区，合计 2,442,240 字节；各槽位 Q 格式不同 |

工作区只有六槽 32 通道 skip 缓冲，每槽 `203,520` 元素，起始偏移依次为 `0、203,520、407,040、610,560、814,080、1,017,600`。偏移单位均为 **INT16 元素**，不是字节。六个 skip 对应 `x1…x6`，小数位依次为 `14、14、14、12、13、14`。卷积中间特征按 8×16 分块放在片上存储。

三次 64 通道拼接依次为 `x3|x4`、`x2|x5`、`x1|x6`，竖线表示沿通道轴拼接：前 32 通道来自左侧，后 32 通道来自右侧。两路在拼接时分别转换到下一深度卷积所需的小数位，依次为 Q12、Q13、Q14。

## 6. 下采样、插值与增强的软件整数规则

以下是**当前软件原型**的准确规则，不能当作后级硬件已经完成的证明。

### 输入和下采样

原图 RGB UINT8，先将宽高向下裁到 12 的倍数；当前固定样例为 `720×1280 → 720×1272`。每个通道按 `round_even(pixel × 16384 / 255)` 得到完整图 Q14，范围 `0…16384`。软件在这一步使用 INT64 容器。下采样比例 12，采用与 `align_corners=False` 对齐的四个采样点平均，再最近偶数舍入并饱和成送给 CNN 的 **INT16 Q14** 小图。

### 参数图双线性插值

输入是 `[1,3,60,106]` 的 INT16 Q14 `A_low`，输出目标是 `[1,3,720,1272]` 的 **INT16 Q14** 参数图，仍采用 RGB 平面 NCHW。坐标与 `align_corners=True` 对齐。软件先横向、再纵向按整数有理权重插值；每一步分子中的乘法及加法使用 **INT64 容器**，除以分母时最近偶数舍入，最终饱和到 INT16。固定尺寸下水平和垂直分母分别为 `1271`、`719`。

### 八轮曲线增强

完整原图 Q14 和完整参数图 Q14 均先转换到 Q15。当前软件的运算容器为 **INT64**，每轮按下式计算：

```text
square = round_even(I × I / 32768)
delta  = round_even(A × (square − I) / 32768)
I_next = clamp(I + delta, 0, 32768)
```

同一参数 `A` 连续用于八轮。每轮结果与最终结果按 **INT32 Q15** 保存；Q15 的 `1.0` 原码是 `32768`，因此不能用有符号 INT16 保存完整的 `[0,1]` 图像范围。最终 `round_even(I × 255 / 32768)`，钳到 `[0,255]`，输出 RGB UINT8 图像。运算符号为 `I + A(I² − I)`。

## 7. 验证与交接边界

当前 CNN HLS top 已用 Vitis 2025.2 C 仿真验证：固定样例的全部 **19,080 个 `A_low` 原码**与软件 golden 一致，最大原码误差为 0。HLS 综合已完成，但其 **40.443 ns** 估计时钟未达到 10 ns 目标；RTL 协同仿真、Vivado 实际时序和板端运行尚未验证。插值与增强的整数规则已有软件参考与测试向量，硬件接口、运算位宽和吞吐实现仍需单独设计并验证。

后级实现建议优先以 `outputs/zero_dce_pp/quantization/integer/night_01_a_low_q14_nchw_le.bin` 作为 CNN→Bilinear 的逐字节输入参考，以逐层测试向量核对插值及每轮增强。更换 DDR/AXI Stream 传输方式时，**不得隐式改变 Q 格式、通道顺序、舍入或饱和规则**。
