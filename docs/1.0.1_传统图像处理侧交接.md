**注意：软件一致性验证通过，不代表 FPGA 已经验证通过。**

## 2. Zero-DCE++ 中你负责哪一部分

完整的计算流程如下：

```text
输入低照度图像
      │
      ▼
  下采样 + CNN       ← 另一位 FPGA 队友负责
      │
      ▼
低分辨率增强参数图 A_low
      │
      ▼
  双线性插值         ← 你负责
      │
      ▼
全分辨率增强参数图 A
      │
      ▼
  八次曲线增强       ← 你负责
      │
      ▼
最终增强图像
```

你这部分的目标是把 **Zero-DCE++ 已确定的非 CNN 计算**实现为 FPGA 模块。

现阶段不是让你另外设计 Gamma、CLAHE 或直方图均衡算法，而是先严格对齐 Zero-DCE++ 的计算过程。

第一阶段可以独立验证计算模块，不必等待 CNN FPGA 模块完成。

## 3. 我提供的参考文件及含义

`.npy` 文件保存的是 Python/PyTorch 计算得到的数组。

这些数据用于 FPGA 模块的输入、输出验证和误差分析。

**FPGA 电路本身不需要直接解析 `.npy` 格式。** 可以通过 Python、C++ Testbench 或板端 PS 程序，将数据转换成实际硬件需要的输入格式。

| 文件 | 含义 | 你的用途 |
|---|---|---|
| `model_input.npy` | 经过 RGB 转换、归一化、尺寸裁剪后，用于增强计算的原图 | 八次曲线增强模块输入 |
| `input_downsampled.npy` | 下采样后供 CNN 使用的小图 | 主要供 CNN 队友使用 |
| `parameters_lowres.npy` | CNN 预测的低分辨率、三通道增强参数图 | 双线性插值模块输入 |
| `parameters_fullres.npy` | 软件双线性插值后的全分辨率参数图 | 插值模块标准输出；八次增强模块输入 |
| `enhancement_iter_01.npy` ～ `enhancement_iter_08.npy` | 第 1～8 轮逐像素增强后的图像数组 | 按轮定位计算误差 |
| `enhanced.npy` | 最终增强结果，对应第八轮输出 | 整体模块标准输出 |
| `metadata.json` | 本次导出的尺寸、数据格式和运行配置等信息 | 确认输入输出约定 |
| `enhanced.png` | 最终图像的可视化版本 | 肉眼观察效果，不作为浮点数值比对标准 |
| `consistency_report.json` | 软件拆分实现与官方前向计算的一致性报告 | 了解软件参考的验证情况 |

当前软件参考约定：

| 项目 | 当前约定 |
|---|---|
| 图像颜色通道 | RGB |
| 张量排列 | NCHW |
| 数值类型 | FP32 |
| 输入图像数值范围 | `[0,1]` |
| CNN 下采样配置 | `scale_factor=12` |
| 增强参数通道数 | 3 |
| 曲线增强次数 | 8 |

当前软件实现让 CNN 在低分辨率下预测参数，再把参数图插值到原图尺寸。

具体张量尺寸以随数据提供的 `metadata.json` 和 `.npy` 实际形状为准。

## 4. 第一项任务：八次曲线增强模块（优先）

### 4.1 任务目标

先跳过 CNN 和插值模块，直接使用：

```text
model_input.npy + parameters_fullres.npy
                   │
                   ▼
            FPGA 八次曲线增强
                   │
                   ▼
             FPGA 最终输出
                   │
                   ▼
            与 enhanced.npy 比较
```

对于每个像素的每个 RGB 通道，连续计算八次：

\[
I_{n+1}=I_n+A\left(I_n^2-I_n\right),
\qquad n=0,1,\ldots,7
\]

其中：

- \(I_0\) 是 `model_input.npy` 中的输入图像；
- \(A\) 是 `parameters_fullres.npy` 中对应位置、对应颜色通道的增强参数；
- 八次迭代重复使用同一个 \(A\)；
- 每一轮都使用上一轮的 \(I_n\)；
- RGB 三个通道独立执行上述运算。

请特别注意公式中的符号。

不要直接改成：

\[
I+A I(1-I)
\]

这会反转当前参数 \(A\) 的作用符号。

### 4.2 第一阶段实现建议

建议先采用浮点实现，确认计算公式、数据顺序和八次迭代逻辑正确。

完成后再考虑定点化。

如果采用定点数，需要记录：

- 输入及参数位宽；
- 中间计算位宽；
- 量化方式；
- 舍入或截断规则；
- 溢出与饱和处理规则。

FP32 软件参考与定点硬件结果不要求逐位一致，需要报告实际数值误差。

### 4.3 如何验证

软件侧已经提供每轮增强后的标准结果：

```text
enhancement_iter_01.npy
enhancement_iter_02.npy
enhancement_iter_03.npy
enhancement_iter_04.npy
enhancement_iter_05.npy
enhancement_iter_06.npy
enhancement_iter_07.npy
enhancement_iter_08.npy
```

可以逐轮比较硬件输出与软件输出，定位误差出现的位置。

最终输出需要与：

```text
enhanced.npy
```

进行比较。

## 5. 第二项任务：参数图双线性插值

第一项任务验证通过后，实现：

```text
parameters_lowres.npy
        │
        ▼
 FPGA 双线性插值模块
        │
        ▼
与 parameters_fullres.npy 比较
```

这一模块需要把低分辨率、三通道参数图放大到输入图像尺寸。

不仅需要输出尺寸正确，还需要对齐仓库中 PyTorch 参考实现的：

- 插值方式；
- 坐标映射；
- 边界处理。

请以实际软件代码为准，不要仅凭通用双线性插值公式假定计算已经一致。

完成后，把插值模块和八次曲线增强模块连接起来：

```text
低分辨率参数图
       │
       ▼
 FPGA 双线性插值
       │
       ▼
全分辨率参数图
       │
       ▼
 FPGA 八次曲线增强 ◄── 原始输入图像
       │
       ▼
最终增强图像
```

这就构成了完整的非 CNN 图像增强计算链路。
