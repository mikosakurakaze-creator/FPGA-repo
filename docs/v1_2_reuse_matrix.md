# V1.2 参考设计复用对照

V1.2 可作为工程连接方式的参考。其 CNN 实现和测量结果属于原低照度系统，不能代替天气候选的验证。下表保留天气系统设计初期的复用判断，后续实际接入结果见 [当前流水版报告](stream_revision_20261020.md)。

| 项目 | 可参考的已有经验 | 天气模块需独立完成或确认的内容 |
|---|---|---|
| PS 控制 | 原设计使用 PS HPM AXI-Lite 控制和 `ap_ctrl_hs`。 | 分配独立天气 IP 控制地址，使用其生成的 CSR/驱动，不能假定旧 CNN 基址和偏移适用。 |
| DDR 地址 | V1.2 使用拆成高/低字的 64 位 DDR 指针，RTL 检查使用 16 字节对齐基址。 | 以天气 top 自身 HLS 元数据和测试确认指针字段、对齐、burst 长度和地址宽度。 |
| 缓冲区所有权 | V1.2 文档说明了缓冲区生命周期和串行加速器调用。 | 将天气 input/output/scratch 的所有权回调接到真实 DMA/cache 操作；天气权重编译在核内。V1.2 板测证据仍将部署用 Linux DMA/cache 标为未验证。 |
| 数据布局 | V1.2 图像使用连续 RGB NCHW 平面、小端 INT16 Q14。 | 天气候选独立采用同一约定，但处理 `[1,3,720,1272]` 全分辨率图像；需用天气 Golden 验证转换与 stride 合同。 |
| DDR 拓扑 | V1.2 将数据/工作区和模型流量分配到不同 HP 端口。 | 分析带宽和仲裁后选择天气连接。原 v1 有 input/output/work master，实验 v2 仅请求 input/output，均无运行时参数 master；HP 分配由系统设计决定。 |
| 计算存储 | V1.2 避免把卷积工作 tile 的每个标量操作都变成 DDR 事务，并记录了片上卷积 tile。 | 天气的层、通道、分辨率、tile、halo 和特征生命周期均不同，需独立设计并测量行/tile 缓存，不能直接套用六 skip 的 2,442,240 字节工作区。 |
| 验证流程 | V1.2 将 RTL、实现、bitstream 和板测分开验收。 | 执行天气数值等价、整帧/tile 边缘、综合资源时序及专用板测；原验收结果不能直接转移。 |
| 吞吐 | 旧 RTL 和板测提供了测试方法，以及区分仿真 FPS 和实际 FPS 的示例。 | C8 在 30 FPS 下的 29.7 GMAC/s 是工作量目标，不能证明天气核达到 30 FPS；需测持续帧率与传输/计算分项时间。 |

## 已有参考证据

- V1.2 交接记录包含正式低照度 CNN IP、bitstream、XSA，100 MHz 布线后无 setup/hold/pulse 失败，八帧 RTL 系统运行约 30.236 FPS。其最近时序摘要为 setup WNS `+0.636 ns`、TNS `0`、hold WHS `+0.010 ns`，无失败端点。
- 独立板测报告记录低照度链单帧和两个不同帧检查，原始输出零不一致、越界保护通过；明确标记 `BOARD_30FPS=NOT_TESTED`，部署用 Linux DMA/cache 管理未完成。
- 这些结果可用于组织 CSR、缓冲区生命周期和验证报告，不能证明天气 HLS 可行、时序通过、板端正确或达到 30 FPS。
