## 可以接受的数值与文件格式

本轮先采用首选 INT16 权重包，bundle 为 `5ff57bb52cff87944261aa1fc68ae556a08a65f1c3d32de702ac47a2bda13710`。ZIP SHA-256 为 `149afa92da36b4cfe7a97f2fd755d1ac471ed46374a6b27a919762fbaf53e715`，5,884 份 payload 校验通过。目前不需要 A 更改数值格式或重导出。

| 项目 | B 的处理和依据 |
|---|---|
| 激活 | signed INT16；全部 320 节点分别取 graph 的 F，实际 F=3..14；输入 F14，输出 F13 |
| 输入 | RGB、NCHW、小端、batch=1；`[-1,1]` 归一化；保留负数；不能复用旧 `[0,1]` 预处理 |
| 权重 | 保留 OIHW / IOHW 原生布局、manifest 字节偏移；先不做 lane 重排 |
| 系数 | 实际 learned coefficient、Q14；各分支独立舍入/饱和后再加，不将两个乘法合并舍入 |
| 算子边界 | conv/deconv、cat、add、ReLU、mulcoef 逐节点对齐；RHAZ 和饱和顺序保留 |
| 反卷积 | 用目标特征 shape 推导输出范围；按目标像素 gather 计算，保持与 IOHW scatter 数学等价；不固定输出乘二 |
| 支持尺寸 | 候选边界 H=4..720、W=4..1280；不拉伸。两组指定大图均已由 B 独立执行完整整数网络 |
| 输出 | 显示前 RGB NCHW INT16 Q13；独立 clamp 和 RGB8 转换由软件侧执行，不将显示结果作 Golden |

B 独立 C++ 的 8 组小图各 320 节点逐元素/字节一致；675×1280 和720×1280 各 320 节点按原始字节 SHA-256 一致，最终 raw 也一致。大图没有输出全部中间 raw，检查采用逐节点实时 SHA，不扩展为逐元素坐标比较。

## INT16 权重与累加器资源

首选参数包为 1,933,120 字节，INT8 备选为 979,904 字节，差 953,216 字节。两者为不同 bundle，现有首选 Golden 不能拿去验收 INT8。保留 DDR 常驻只读参数，按 tile 将所需权重缓存到片上，避免把约 1.93 MB 权重全塞进 BRAM。

独立使用实际量化权重与 bias 重算每输出通道 `32768*sum(abs(w))+abs(bias)`：

| 版本 | 最大绝对累加界 | 至少有符号位宽 | 当前选择 |
|---|---:|---:|---|
| 首选 INT16 | 286,417,368,313 | 40 | CPU INT64；HLS MAC/舍入临时量使用48位 |
| INT8 备选 | 1,118,937,525 | 32 | 本版实际权重可证明 MAC 在 INT32 内；不据此切换版本 |

40 位界覆盖所有 signed INT16 输入、bias 与任意部分和，不能缩成 INT32。HLS 采用48位，仍保留每节点饱和；cat/add 尺度提升也在宽整数内进行。INT16×INT16 乘积完整保留为32位。既有 DSP 符号改写风险需要最终 opt/routed 网表回归继续核验，HLS 仿真不能替代这个门禁。

已真实完成一个复用卷积 tile 核的 HLS 综合：8 输出通道、16×16 输出块，输入缓存 41,472 个 INT16 槽，当前图所需上界36,288槽；权重按通道分bank，MAC 内没有 DDR 引用，完成后写回。HLS 报告为 LUT17,392、FF9,796、BRAM18K73、DSP67、URAM0，估算周期7.300ns，目标10ns。5组含奇数目标 deconv 的 Vitis C仿真全对。

这些资源仅对应算子核，不含最终 descriptor 调度、逐元素核、SmartConnect或其他系统IP。8条乘法lane不代表综合结果只用8个DSP；地址与控制运算也会映射资源。动态顶层延迟报告为undef，没有据此给出整图耗时。720p严格卷积计数含deconv边界乘积为263,120,486,400 MAC；8 lane、100MHz的纯MAC理想下界约329秒，尚未包含DMA、缓存装载和调度。它是选型预算，当前单张图无FPS门槛，后续根据真实耗时再增大并行度。

随后新增逐元素 HLS 核，Vitis 48 位 C 仿真对齐208个节点和6,921组边界；幅值移位优化后的综合估算 LUT11,419、FF5,899、BRAM18K7、DSP13、URAM0，估算周期7.300ns。两类算子仍没有PL图调度器和系统互连；整图8组小向量通过的是主机调用HLS源的原生INT64执行。旧系统正式routed用量为LUT74,047、DSP961，不能套用早期23.1%LUT的余量。具体见integration_scope_20261024.md。

## DDR scratch 与缓存方案

先顺序执行冻结的320节点，不进行整网空间裁剪。不沿用旧halo=6。每个卷积输出按16×16 tile计算，使用该算子精确坐标取局部输入；跨层中间结果按节点边界写回DDR，因而没有跨多尺度整网halo猜测。cat先物化，逐节点尺度转换，完整保留通道次序；后续虚拟cat必须证明多次舍入/饱和仍等价。

本轮给出每个节点的实际相对地址、64字节对齐长度、birth/last_use和复用范围，全部寿命相交地址不重叠。该地址计划也用于B C++整网实际运行，并非只有容量算式。

| 尺寸 | 输入/输出各自长度 | 理想逻辑存活峰值 | 当前地址分配scratch |
|---|---:|---:|---:|
| 33×47 | 9,306 B | 599,712 B | 794,240 B |
| 675×1280 | 5,184,000 B | 331,816,960 B | 442,368,000 B（421.875 MiB） |
| 720×1280 | 5,529,600 B | 353,894,400 B | 471,859,200 B（450 MiB） |

720p输入、输出、原参数blob、scratch合计484,851,520字节（约462.39MiB），不含命令、shift元数据和DMA分配器额外开销。可将512MiB作为平台容量规划预算；这不是要求立即改启动参数，也不是已经分配成功。物化逐节点特征一次读写的理论流量下界19,305,676,800 B/图，分块重读还会增加；不得继续使用旧模型11 MB/帧预算。

450MiB单一连续DMA分配可能超过当前CMA可用或连续容量。实际CMA、DMA mask、驱动限制及碎片化情况尚未取得。先采用输入/输出/参数/元数据/临时区各自coherent DMA句柄和长度；如果平台不支持单一scratch，必须改成按张量池/分段地址描述的分配方案并重新核对每节点边界，不能默默假定可寻址。

## DMA 与控制方案

PL通过m_axi访问DDR；不额外引入AXI Stream/AXI DMA。输入/参数/命令读取拟复用HP0，特征读写与输出经明确调度的HP口；首版可按读HP0/写HP3接入，但scratch读也必须接到同一合法DDR窗口。已核验算子生成RTL：read_mem数据64位、write_mem数据32位、两路地址64位；AXI-Lite数据32位。最终PS侧宽度仍需再查BD/XSA，不能把128位widen配置请求当作已生成总线宽度。

软件侧负责PS上的图片预处理、已校验参数上传、coherent DMA分配、ownership锁、请求与错误处理；B组交付这些操作所需的硬件寄存器/内存合同，不接管Linux驱动适配。整网算子和图遍历计划放在PL执行。本轮已有整网CPU执行器用于验证，不是最终让ARM执行剩余算子。权重同bundle加载一次复用，输入/输出/临时区每次job保持独占。

新整网ABI需要独立model ID、ABI版本、参数bundle绑定；输入/输出/weights/scratch/command分别是64-bit DMA地址加长度，H/W和错误码明确。模型ID建议GDN1，旧task=1不可识别为新网络。提案见 `interface_proposal.md`；当前真实已导出的只有算子测试核CSR，不作为完整图片ABI发布。

成功DONE必须同时代表结果有效和所有AXI写响应已收齐；超时属于完成未知，驱动保留所有可能被DMA使用的buffer，直到专用复位/排空证据成立再释放。禁止操作共享PS复位或全局SMMU绕过来临时恢复。
