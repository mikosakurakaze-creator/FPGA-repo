# 保留旧系统、增加独立去雾核

2026-10-24 用户已确认：“保留旧核新改一个新的去雾核吧”。最终集成范围据此确定；这份决定不等于新整网硬件已经完成，也不包含 Git 提交或推送授权。

用户随后限定本轮只负责FPGA加速器、DDR调度及综合实现，最终交付bit/XSA。上传、驱动适配和HDMI显示由外部软件侧负责，不属于本轮任务；完整责任与硬件交付条件见responsibility_boundary_20261024.md。

原仓库的正式参考为 `weather_fpga_integration` 分支 `e8662ce5bd177f4014da469ab9885eca06e396f3`，正式发布目录为 `board/releases/k26_weather_v2_signedfix_20261023`。新工作位于独立 `competing/griddehaze_fpga`，本轮不就地覆盖旧发布物。

## 独立新核的结构

新核内部使用一个复用的缓存卷积/反卷积引擎、一个逐元素引擎以及已新增的 PL 图调度器，执行冻结的 320 节点。卷积采用 INT16 权重与 48 位累加；逐元素引擎完成 ReLU、系数乘法、加法、拼接，逐节点保留 RHAZ 和饱和边界。内部算子接口与真实整图 ABI 分开，当前整图候选合同见 `frame_interface.md`。

PL 调度器由 B 实现，负责节点顺序、tile 遍历、缓存装载、DDR 中间结果及完成通知。软件侧负责 PS 上的参数校验/上传、图像预处理、DMA 内存和请求生命周期；Linux 驱动适配不属于本用户的 B 组任务。B交付控制、地址、长度、完成与错误合同，不将剩余算子交给 ARM 计算以冒充整网硬件。

首版采用节点结果写回 DDR 的方案，720p scratch 为 471,859,200 字节（450 MiB）。输入、输出、权重加 scratch 共 484,851,520 字节，另需 1,344 字节 layout 和分配对齐开销；shift 已固化为片上 ROM，不另设 DDR shift 表。不能沿用旧网络的小内存预算；实际 Linux DMA 分配还未验证。

## 现有平台接入依据与边界

读取了旧工程的真实 `system/create.tcl`：旧 weather 控制接在 `axi_control/M03_AXI`，DDR 读经 `cnn_data_sc/S03_AXI` 到 HP0，写经 `curve_ddr_sc/S03_AXI` 到 HP3，旧 weather 控制基址为 `0xA0030000`，该核的两个 DDR 地址空间限制在低 2 GiB。新核须新增 SmartConnect 从接口和控制出口，不占用或覆盖旧核入口。新基址、最终总线位宽及地址窗口必须从新 BD/XSA 导出核对，当前不写成已部署值。

初版软件应在旧、新处理路径之间持有共同的请求锁，避免未验证的并发 DMA、复位和带宽竞争；每个新 job 的输入、输出、参数与 scratch 在运行期间独占。时钟可参考原 100 MHz，但新系统必须重新综合、布局布线并通过时序。新核的故障恢复须具有设备专用复位和 AXI 排空依据，不能复位共享 PS/低照度/旧 weather 来恢复单个请求。

## 资源依据

旧正式发布的 routed 报告是 LUT 74,047/117,120（63.22%）、FF 79,552/234,240（33.96%），setup WNS +0.638 ns、hold +0.010 ns。它不是早期 V1.1 的 23.1% LUT 数据。

新卷积 tile 的 HLS 估算为 LUT 17,392、FF 9,796、BRAM18K 73、DSP 67，估算周期 7.300 ns。旧布局布线用量和新 HLS 估算只可用于初筛，不能相加后宣布系统一定放得下或通过 100 MHz。逐元素核、调度器、新互连和拥塞还需纳入完整实现。

新增逐元素核经幅值移位优化后的实际 HLS 估算 LUT 11,419、FF 5,899、BRAM18K 7、DSP 13、URAM 0，估算周期 7.300 ns。旧系统 DSP 为 961/1248，BRAM tile 为 72/144，URAM 为 47/64。粗略将旧 routed 与两个新核 HLS 用量相加得到 LUT 102,858/117,120（87.82%）、DSP 1041/1248（83.41%）、BRAM18K 当量 224/288（77.78%），尚未计调度器和互连；这是预算，不是新系统真实综合或布局布线结果。特别需要控制 LUT 和布线拥塞，不能按空余 DSP 数无限增加卷积并行度。

## ZIP 中的平台材料核查

本轮 GridDehazeNet ZIP 没有当前板端 coherent DMA 驱动、设备树或实际 CMA 读数；Fog/Rain/archive 为数据。旧 C8 ZIP 含 HLS 自动生成的寄存器访问驱动，Linux 文件采用 UIO，不能以此证明板上 450 MiB coherent DMA 分配能力。仍需与软件侧实际使用的驱动/DT 对齐，但这不阻止先完成算子及图调度器开发。
