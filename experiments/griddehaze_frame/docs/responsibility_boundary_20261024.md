## 谁负责什么

| 事项 | 责任与交付 |
|---|---|
| A 组 | 冻结整数语义、权重、逐节点尺度与 Golden |
| B 组（本工作目录） | 新去雾核、PL 整网调度、DDR 地址与生存期计划、缓存、控制/状态/错误接口、设备级复位与完成语义、Vivado 系统集成、综合和布局布线 |
| B 组最终交付 | bit/XSA；附硬件地址/寄存器/内存合同、构建与验证报告和文件校验值，便于外部软件侧接入 |
| 软件侧 | Linux coherent DMA 驱动适配、设备树在目标系统中的合入与部署、实际 DMA 分配、请求锁与超时处理、上传服务、图像预处理/显示及下载、上板执行 |
| 双方共同确认 | 新硬件可寻址范围与软件 DMA 地址一致、缓冲区大小/对齐、设备复位和未完成 AXI 事务处理；板端核对整数结果和边界 |

B说明最终硬件实际基址、范围、中断、时钟等资源，外部软件侧据此编写或调整设备树。B不开发上传服务、Linux驱动或HDMI程序，不修改目标系统的reserved-memory、CMA或SMMU配置。硬件错误、排空和独立复位的能力仍须B设计并举证。

## 本轮硬件完成条件

1. 保留旧weather和低照度模块，新增独立GridDehazeNet加速器；整网计算和DDR调度在PL执行。
2. 新核数值与冻结整数Golden对齐，DDR边界与硬件控制语义有验证依据；完成所需RTL及实现电路验证，不能仅以CPU/HLS结果宣布硬件完成。
3. 完成包含新核的系统综合、布局布线和目标时钟检查，报告真实资源、时序、路由状态及未解决问题。
4. 导出同一已验证硬件构建的bit/XSA并记录身份、接口和构建依据，供外部软件侧接入。

上传、驱动适配、设备树部署、HDMI及板端实际DMA分配不计入本轮B组实现任务。外部软件完成前，不声称整套系统已上板通过或720p请求已运行成功；硬件交付状态与系统联调状态分别记录。

## DMA 驱动和 CMA 不再列作硬件开工前置

之前将“没有拿到现有驱动、设备树和 CMA，所以 bit/XSA 依赖这些信息”连在一起，范围过大，现予更正：

1. B 继续完成新核、图调度、硬件地址检查、系统互连、综合实现与硬件导出；不要求本用户先编写或寻找驱动才能推进。
2. B 交付明确的 DMA 输入条件和资源定义，由软件侧据此适配。尚未共同冻结的地址范围、内存布局和恢复语义必须标为候选，不能冒充已联调。
3. CMA 实际容量和 DMA 分配成功与否属于板端部署与验收证据，不是离线 HLS/RTL、综合或布局布线的必要前置。没有这份证据仍不能称为“板端 720p 已可运行”。
4. 当前 450 MiB scratch 是 B 当前地址计划的需求，不是要求用户修改启动配置的指令，也不是已证明板端可分配。若软件侧反馈容量或地址限制不兼容，B 要调整分段/张量池或内存复用方案，并重新验证，不能只让软件扩大 CMA。
